# Projection-Model Audit — July 2026

A four-track code audit of the projection models, run against HEAD (76026df):
MLB, the shared generic engine + football, NHL/soccer/tennis + the prop
distribution layer, and the evaluation/calibration/edge layer. Every finding
below was verified against actual code (file:line), and the highest-impact ones
were reproduced numerically or confirmed with live API probes. Items the
roadmap already tested and parked (wind, xwOBA blend, recency decay, SoS,
pooled prop calibration) were deliberately excluded.

**Headline:** the modeling math the roadmap validated is largely sound (NB
parameterizations, de-vig, park de-bias, walk-forward hygiene in `backtest.py`
all check out). The damage is concentrated in (1) one production-killing typo,
(2) the data feeds the live models eat — which differ materially from what the
backtests validated — and (3) EV/staking plumbing that leaks money even where
the projections are right.

## P0 — Critical, fix immediately

### 1. `SPORTS[sport]` typo silently kills ALL edges for every generic sport — `pipeline.py:1317`
Found independently by three audit tracks. In `attach_generic_game_edges`'s
totals branch, `shrink=SPORTS[sport].market_shrink` indexes the `SPORTS` dict
with the `Sport` dataclass instance (bound at `pipeline.py:1247`) instead of
the key — the moneyline (1282) and spread (1357) branches do it right. `Sport`
is a frozen dataclass carrying a dict field (`espn_params`), so hashing raises
`TypeError: unhashable type: 'dict'` on the first game with a matched totals
offer. The exception aborts the whole `games.apply(...)`, is swallowed by the
catch-all at `pipeline.py:1816-1821`, and the pipeline serves **model-only
games: no moneyline, total, or spread EV for the entire NBA/WNBA/NFL/NCAAF/NHL
slate** whenever BettingPros quotes a total (i.e. essentially always in
season). The comment at `pipeline.py:1810-1813` quotes this exact error string
and misattributes it to "a malformed odds payload" — the bug has fired in
production and the workaround institutionalized it. Downstream: no plays, no
ledger rows, no gate CLV can accumulate for generic sports.
**Fix:** `shrink=sport.market_shrink` (one token) + a regression test that
exercises the totals branch with a stub offers frame (the resilience tests
monkeypatch this function away: `tests/test_pipeline_resilience.py:58,126`).

### 2. Integer-line pushes are priced as losses (over side) and wins (under side) — `odds.py:33-36`, `pipeline.py:88-92`
Found independently by three tracks; live in today's `latest.json` (7 MLB
games at integer total lines). Every `prob_over` in the system is strict-over
(push-excluded) — correct — but `_market_eval` prices the counter side as
`1 − p`, which equals P(under) **+ P(push)**, and `expected_value` treats a
push as a full loss for the side bet. Measured push mass at a 9.0 MLB total
under the model's own NB draws: **≈8.6%** — dwarfing typical 2–5% edges. The
board is systematically tilted toward unders on every whole-number total,
spread, and prop line (MLB totals 8/9, NHL 6.0, Ks 6.0, outs 18.0…). The
comment at `props.py:38` claiming "pushes are handled by the caller's odds" is
false — no caller handles them. The grading layer handles pushes correctly
(`plays.py:138-139`), so these phantom edges later grade as pushes.
**Fix:** compute `p_win / p_push / p_lose` explicitly at integer lines,
`EV = p_win·(dec−1) − p_lose`, condition Kelly on `1−p_push`, and blend the
*conditional* model prob `p_over/(p_over+p_under)` toward the market fair.
One change in `_market_eval`'s contract fixes totals, spreads, and props at once.

### 3. Kelly stakes are sized on the raw model probability while bets are selected on the calibrated/shrunk one
Two independent tracks found the same pattern at different call sites:
- Game markets: `app/ui.py:1975,1991-2003`, `workbook.py` (pinned by
  `tests/test_workbook.py:197`), `sgp.py:81` — EV comes from `_market_eval`
  (calibrate → shrink toward market) but `odds.kelly_stake(prob,…)` gets the
  raw `home_win_prob`/`model_over_prob`.
- Soccer: `pipeline.py:1222-1233` builds the Kelly `p_map` from raw
  `home_win_prob`/`draw_prob`/`over_2_5` while EVs (1206-1219) use the blend.

By the repo's own T0.1 finding the raw model prob is the most over-confident
number available; sizing on it roughly doubles the intended ¼-Kelly at typical
prices, precisely when the model is most wrong. The tennis and props paths do
it right (`pipeline.py:1110-1115`, `pipeline.py:684` use `ev["p_used"]`).
**Fix:** thread `p_used` out of `_market_eval` (e.g. `home_ml_p_used` columns)
and stake from it everywhere.

## P1 — Data-integrity bugs feeding the live models (train/serve skew)

The committed-backfill backtests that validated the tuned constants never see
any of these; live behavior is strictly worse than validated behavior.

### 4. ESPN results truncation: NCAAF capped at the oldest 400 events per 150-day chunk — `sports.py:147`, `espn.py:22-23,393-417`
`espn_params = {"groups": 80, "limit": 400}` is merged into every request,
including `results_range`. Live probe: a 2024-08-24→2025-01-20 query returns
exactly 400 events spanning **Aug 24 → Oct 5** (964 exist at limit 1000). From
mid-October on, NCAAF `team_ratings` sees no recent games — by bowl season
"form" is entirely August/September and the 500-day Elo replay loses ~half of
each season. NBA/NHL hit the same wall at the default 1000 cap: a dense
mid-season 150-day chunk returns exactly 1000 events and silently drops the
tail (~100 NBA games; live-probed). **Fix:** override `limit` in
`results_range`, detect `len(events) == limit`, and page or shrink chunks.

### 5. Elo "season" is the calendar year — regression fires Jan 1 mid-season, never in the real off-season — `pipeline.py:942-944,971-973`, `elo.py:36-42`
Found independently by two tracks. Every NFL team is pulled 33% toward 1500
right before the playoffs; NCAAF 45% before the bowls; NBA 25% and NHL 30% in
mid-January — and since June and the following October share a calendar year,
the intended off-season regression (the only one roster turnover justifies)
never happens. WNBA — the league the Elo was tuned on — is the only sport
where the labeling works. The backtest shares the convention
(`backtest.py:710,852`), so tuned `elo_regress` values partially bake the bug
in; `_generic_games` already carries a true `season` field (`backtest.py:318`)
that is ignored. **Fix:** sport-aware season label (`year − 1 if month < 7`
for NBA/NHL, month < 8 for NFL/NCAAF) in both live replay and backtest, then
re-sweep `elo_regress`.

### 6. Preseason/exhibition games pollute ratings and Elo — `espn.py:28-57,411-414`
No season-type filter anywhere. Live probe: NFL `dates=20240801-20240910`
returns 65 events of which **49 are preseason**. September/October NFL form
windows and the full-k Elo replay ingest backup-QB preseason scores (plus Pro
Bowl / All-Star events). **Fix:** parse `ev["season"]["type"]` in
`_parse_events` and drop non-regular/post types in `results_range` and the
Elo replay.

### 7. MLB temperature multiplier applied to dome/closed-roof games — `weather.py:37-80`, `pipeline.py:283-289` vs `backtest.py:146-147`
The pipeline comment claims `game_weather` returns None for domes; it has no
dome logic at all — it returns the outdoor Open-Meteo forecast for every park,
including TB and the retractable roofs (ARI, HOU, TEX, MIA, MIL, TOR). The
backtest that validated `TEMP_COEF=0.003` **excluded** dome/roof games, so the
live model applies an outdoors-validated coefficient to a Phoenix/Houston
summer forecast of 95–105°F (~+0.7 runs toward the +8% clamp) for games played
at 72°F indoors — a quarter of home venues, worst exactly in summer.
**Fix:** dome/roof table in `weather.py` (fixed domes → None; retractables →
None outside a comfort band), mirroring the backtest's exclusion.

### 8. NHL box scores never ingested; NHL prop grading finds no logs after Jan 1 — `playerlogs.py:311-317,237`, `espn.py:257-298`
`ingest()` has no NHL branch (its own docstring claims otherwise) and
`box_player_logs` has no hockey stat mapping, so the forward store only grows
via manual `import_nhl_skaters.py` runs — the committed backfill ends
2026-04-17, so the entire 2026 playoffs were priced on frozen data and never
graded. Independently, `actual_value` loads logs for `int(date[:4])` only,
but NHL backfill rows are labeled by season *start* year, so grading any
Jan–Jun NHL prop returns None even where data exists. **Fix:** NHL branch in
`box_player_logs` + `ingest()`; make `actual_value` load `{Y, Y−1}` like
`hit_rates` does.

### 9. MLB stat tables drop doubleheader game 2 and merge same-named players — `internal_stats.py:91,143,197`
`drop_duplicates(["norm_name","date"])` deletes the second game of every
doubleheader and collapses distinct same-named players; aggregates group by
`norm_name` even though `player_id` is available. Same pattern in the prop
layer: `playerlogs.py:119` dedupes `(name, date)`, and `hit_rates` /
`actual_value` ignore the role filter their own market table defines
(`playerlogs.py:182,239` — `pitcher_hits_allowed` vs `batter_hits` share a
column). **Fix:** key on `player_id`/`game_pk` with name fallback; apply the
role filter.

### 10. Shared cache key can permanently ingest a partial MLB box score — `mlb_statsapi.py:165,199,441`
`box_score` (45s TTL), `game_officials` (15min), and `box_player_logs` (24h)
share the key `statsapi:box:{game_pk}`. The hourly job projects before
ingesting; a game going final in between lets the 24h reader accept a
mid-9th-inning snapshot, and the idempotent `game_pk` skip means truncated
rows are never repaired. **Fix:** separate cache key for ingest (or verify
game state is Final before ingesting).

## P2 — Model-correctness fixes (validated levers, wrong constants/plumbing)

### 11. MLB home-field delivers 51.2% where the config targets 53–54% — `config.py:75-76`, `game.py:125-128,174-178`
Reproduced with a 400k-draw neutral-matchup sim: `HOME_FIELD_RUNS = 0.12`
yields home win prob **0.512** against the config's own "~53-54%" comment.
±0.06 runs is too small under the NB distribution, and the extra-innings
tie-break is perfectly symmetric (no walk-off/last-at-bat structure, which is
what converts ties into home wins in reality). Every home moneyline is
under-priced ~1.5–2pp. **Fix:** don't inflate `HOME_FIELD_RUNS` (that distorts
totals to fix a win-prob problem); tilt the tie-break (P(home wins the extra
frame) ≈ 0.52–0.54) or apply a small post-sim shift, validated walk-forward.

### 12. Lineup engine's league-wOBA anchor is stale — `game.py:52-66`, `batwoba.py:29-52`
`wraa = 38·(wOBA − 0.318)/1.20` uses a hardcoded anchor while the live input
is real Statcast wOBA. PA-weighted league wOBA in the committed files:
2022 = .3097, 2023 = .3184, 2024 = .3102, 2025 = .3131, 2026 = .3173. In a
.310 environment every lineup reads ~.008 "below league" → ~−0.18 on the total
at LINEUP_BLEND=0.35, pure anchor drift — and 2024 (the validation season) had
the worst error, so the lever's measured gain likely *understates* its value.
`WOBA_RUN_SCALE=1.20` is similarly static. **Fix:** compute the anchor (and
scale) from the same `statcast_xstats` file at load; keep 0.318 only for the
proxy path (which is anchored to it by construction).

### 13. T1.3 still open: published side scores/total contradict the published margin — `generic.py:197-224`, `pipeline.py:979-982`
`with_consistent_margin` rewrites `margin_mean` from the blended win prob but
leaves `home_exp`/`away_exp`/`total_mean` untouched, so
`home_exp − away_exp ≠ margin_mean` on every Elo/rest-blended game — an
internal contradiction in the exact "Team A x.x / Team B y.y" numbers the
roadmap targets. Cheap fix already sketched in the docs:
`home_exp = (total+margin)/2`, `away_exp = (total−margin)/2`. Prerequisite for
a coherent T3.1. Related: NFL's `sigma_margin` was inflated 13.5→16.0 as a
calibration knob, which now also stretches every published NFL margin ~18%
(`sports.py:125-129`, `generic.py:219`) — decouple when T3.1 lands.

### 14. NHL: Elo moves the moneyline only; puck line and totals never see it — `generic.py:141,212-218,244-246`
`with_consistent_margin` is an explicit no-op for Poisson sports, so the
puck-line cover is priced off raw lambdas while the ML carries a 0.50 Elo
blend — the same "silent inconsistency" the function exists to prevent.
Also: `prob_over` uses regulation-only lambdas while books settle totals
including OT/SO (~23% of games add a goal → systematic under-bias), and the
sim's OT loop can resolve ties at +2/+3 margins (impossible in real OT),
overstating −1.5 covers. **Fix:** back-solve a lambda shift to match the
blended win prob holding the total; resolve simulated ties by awarding exactly
one goal with prob `lam_h/(lam_h+lam_a)`; add the expected OT increment to the
totals distribution.

### 15. Neutral-site flag dropped — football HFA + Elo home edge applied to bowls, Super Bowl, internationals — `espn.py:28-57`, `generic.py:107-111`, `elo.py:47`
Known from the research docs, confirmed unfixed; ~2 points of spread error on
every neutral NCAAF game (hfa 2.7 + 65 Elo points). MLB variant: neutral-site
games use the home team's park factor and home-city weather
(`pipeline.py:281-289`) — Mexico City altitude alone is a >1.3 park factor.
**Fix:** surface `competition.neutralSite` (and StatsAPI venue id), thread a
`neutral` bool through `expected_score`/Elo.

### 16. Tennis: unseen/TBD players priced at Elo 1500 with no sample gate — `pipeline.py:1060-1069,1100-1118`, `espn.py:343-351`
Live in today's output: dozens of ATP rows with `p1_matches: 0`, including
literal "TBD vs TBD" and "TBD vs Sinner" at 0.1035. Only the accident of no
matching odds kept EVs null. The props layer already solves this
(`MIN_GAMES = 5`); tennis computes `elo.seen()` and ignores it. **Fix:** skip
EV/Kelly when `min(p1_matches, p2_matches) < 5`; drop TBD entrants in
`_parse_tennis`.

## P3 — Evaluation & wagering-layer gaps (make the measuring stick honest)

### 17. Under-side totals and all spreads are staked but never graded into the ledger — `results.py:179-201`
`grade_date` grades moneylines and the **over side only**; no reference to
`under_ev`/`spread_home_ev` exists in `results.py`. Meanwhile curation pushes
unders (`plays.py:245-251`) and the UI stakes spreads. Consequences: one-sided
selection bias in the forward ledger; the edge gate evaluates `(sport,"total")`
on half its population; "spread" can never produce a ledger row so it sits in
PROBATION at half-Kelly forever with no mechanism to learn. **Fix:** grade
unders and spreads symmetrically; until then zero-stake spreads rather than
probation-stake them.

### 18. Totals CLV compares different lines via a biased best-of-book de-vig — `results.py:200`, `clv.py:41-71`
Bet Over 8.5, closes 9.5 → your price is scored against fair-P(over 9.5);
`tot_close["line"]` is captured and unused. The closing "fair" comes from
best-over/best-under across all books at any line (hold sometimes < 1.0 →
close silently dropped at `odds.py:65`). The gate's CLV floor decisions
consume exactly this field. Same alt-line pooling inflates the backtest
(`backtest.py:459-482`: median line, max price across different lines —
phantom EV and a free half-run) and the live +EV scanner
(`edge.py:236-241`: totals prices compared across books at different lines →
phantom arbs). **Fix:** de-vig per book (both sides, same line), average
across books — as `backtest._devig_market` and `edge.market_consensus`
already do for MLs; record the closing line; skip or convert CLV when the
line moved; group two-way markets by (book, line).

### 19. `avg_clv_vs_fair` is not CLV — it's signed home-side model-vs-market bias — `backtest.py:754,796`
`hwp − home_fair` for every matched game, always home-perspective, on the raw
(not deployed) prob. A model with huge symmetric noise scores ≈0. It's the
headline number in `run_backtest.py` reports and the tune_calibration sweep.
The correct per-bet harness exists (`run_mlb_clv_open_close`,
`backtest.py:964-1044`) but only for MLB/2026. **Fix:** per-placed-bet CLV,
signed by side, on the deployed probability; rename the current field
`home_prob_bias`.

### 20. No evaluation path reproduces the deployed pipeline; shrink is tuned in-sample on units
Production applies calibration then shrink (`pipeline.py:62-75`);
`run_game_backtest` applies neither (default `shrink=0.0`, no `calibrate`
reference); `fit_calibration._ml_roi` validates calibration without shrink;
`tune_calibration.py` sweeps shrink without calibration, maximizing realized
units in-sample over 4 grid points — close to picking noise, and inheriting
finding 18's inflated totals ROI. **Fix:** add `apply_calibration` +
per-sport `shrink` flags to `run_game_backtest` so one run reproduces
production; tune shrink on holdout CLV/log-loss, not in-sample units.

### 21. Edge gate: no variance term, and it grades a population it doesn't gate — `edge_gate.py:92,99-112`, `config.py:205-210`
CLEAR requires `clv_n ≥ 30, avg_clv ≥ 0`: with per-bet CLV σ of a few percent,
SE at n=30 is ~0.5–1% — marginal markets clear or miss on noise, then get
full Kelly. The ledger rows averaged include 6–8% WATCH and ≥8% VERIFY bets
the curation layer never pushes (stale lines have the worst CLV by the
system's own thesis). `HELD_MARKETS` holds NBA/NFL/NHL moneylines but not
those sports' totals, which the T0.1 table condemns equally — they earn
half-Kelly in probation today. **Fix:** gate on `avg_clv − z·SE ≥ floor` (or
a Wilson bound on the already-computed-and-unused `clv_pos_rate`); restrict
gate stats to the curated EV band; extend the hold to the condemned totals.

### 22. Smaller evaluation items
- NFL/NCAAF ties graded as home ML losses; books push (`backtest.py:732`,
  `results.py:128-135`).
- ±1-day closing-line matching can grab the adjacent game of an MLB series;
  doubleheaders share one consensus key and one ledger dedup key
  (`backtest.py:64-80`, `results.py:95`) — key on game_pk/event id.
- Production calibration map is refit on train+holdout after gating (standard,
  but the published quality stats describe a map that wasn't the one
  validated) (`fit_calibration.py:184`).
- De-vig method inconsistency: multiplicative in backtest/clv vs power in
  `edge.py` (`calculators.py:23-42`) — pick power everywhere; multiplicative
  slightly flatters the "market baseline" at the extremes.
- Retro re-runs of `pipeline.run` for past dates have lookahead
  (`mlb_statsapi.py:241-273` endDate inclusive; season-to-date tables) —
  document that historical evaluation must go through `backtest.py`.

## P4 — Untested levers worth trying (not in the parked list)

Ordered by (evidence × effort). House discipline applies: behind a knob at 0,
walk-forward vs the T0.1 market baseline, then turn up.

1. **T3.1 market-anchored published projection — confirmed absent, all
   ingredients exist.** `odds.blend_toward_market`, open-line capture
   (`backtest.bp_open_close`), the open→close CLV tuner, and a dormant
   `"blend"` tracking source (`tracking.py:32`) are all in place. Anchor to
   the **open/current** line (never the grading close), per-market weight
   tuned on open→close CLV, keep `_market_eval`'s shrink separate for
   selection, reconcile through `with_consistent_margin` (needs #13 first).
   Per the T0.1 table this is the single largest accuracy win available for
   the published numbers.
2. **MLB per-start expected innings** (`props.py:57-76` plumbing already runs
   in `project_props`) → replace the fixed 5.3/9 starter share in
   `expected_runs` (`game.py:84`). A 4-inning-limit starter in front of a bad
   pen is currently priced as a 5.3-inning starter.
3. **MLB bullpen fatigue** — computed and displayed
   (`internal_stats.py:114-132`), never applied; scale `opp_bullpen_xfip` by a
   small factor when the pen is "heavy" (`BULLPEN_FATIGUE_COEF=0` knob).
4. **Re-test hoops pace×efficiency with the possession formula fixed** —
   `hoops.project_points` accepts `league_pace` and never uses it;
   `poss = 0.5*(home+away)` halves pace deviations (standard form:
   `home + away − league`). The parked verdict ("worsens totals") may rest on
   this bug; re-running `validate_hoops.py` is cheap and legitimate.
5. **Soccer rho+HFA profile fit** — 30-line stepping stone to T2.4: hold
   generic `(h_exp, a_exp)` fixed per historical match, grid-search
   rho ∈ [−0.25, 0] × hfa ∈ [0.1, 0.5] on walk-forward 1X2 log-loss.
   Validates or refutes both hand-set constants before committing to the full
   MLE. Also: price totals at their posted line instead of only 2.5
   (`pipeline.py:1154` skips 2.75/3.0/3.25 quotes), and request/price BTTS —
   the model already computes it (`pipeline.py:1034`).
6. **FantasyPros ensemble into MLB game runs** — pulled and persisted daily,
   blended into every prop, never aggregated into team runs; FP history is on
   disk so a walk-forward validation is possible.
7. **Platoon forward-CLV A/B** — `batwoba.lineup_woba` implements the platoon
   nudge; the live call site passes neither `starter_throws` nor
   `starter_share` (`pipeline.py:312-317`) though both are already computed
   for props. One call-site change starts the A/B the roadmap says it wants.
   (Fix the stale "this module is inert" comments at `batwoba.py:26-28` too.)
8. **Re-fit prop NB dispersion on the served blend** — the fitted `r` values
   were fit on the model-only rate but production serves a FP/BP/model blend
   (`pipeline.py:1631-1668`); extend the validator's line set beyond
   `round(proj)±0.5` to cover integer and alt lines.
9. **MLB extra-innings ghost runner** — tie-break uses `Poisson(mu/9)` per
   half-frame; real extras score ~1 run/half since 2020. Totals in ~9% of
   games understated 0.5–1 run (`game.py:170-178`).
10. **Proxy pseudo-wOBA shrinkage** — the Statcast path PA-shrinks, the
    AVG/SLG fallback doesn't, and it's used exactly for the thinnest samples
    (`pipeline.py:211-226`); apply the same `pa/(pa+40)` shrink. Derive
    `LEAGUE_RUNS_PER_GAME` / league-FIP anchors annually from committed logs
    instead of hand-set constants (4.10 vs 4.20 disagree in-repo today).
